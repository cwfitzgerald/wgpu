## Top-level comment (reply to the review body)

Review: https://github.com/gfx-rs/wgpu/pull/8388#pullrequestreview-5435859783

> How to read the branch: it is rebased on trunk. The original six commits are unchanged, and every fix is its own commit on top, so you can see what is new. I will squash the fixes into the original six at the end.
>
> - Commit messages: the fix commits have a title only. The six original commits get short messages at the squash.
> - Code size: on a Vulkan-only Windows app, +102,912 bytes (+1.85%) for a default release build and +56,832 bytes (+1.53%) size-optimized. It is a fixed cost that the linker cannot remove. I did not add a cargo feature; we can add one if someone needs it.
> - Queue transfer: implemented. On present, the back buffer is released to `VK_QUEUE_FAMILY_EXTERNAL` in `GENERAL`, and a later use in the same frame does the matching acquire. At frame start the texture is `UNDEFINED -> X`, which is a valid implicit acquire because the contents are not needed. I used `EXTERNAL`, not `FOREIGN`, because the D3D12 device is on the same LUID-matched adapter and driver. Native swapchain and imported textures are unchanged.
> - Failed submit and hangs: `wait_for_value` now waits on an event with a 1 s timeout and returns `Lost`, in acquire, present and teardown. Teardown also signals any unsubmitted `vulkan_progress` values from the CPU after `device_wait_idle`, so it cannot hang. I did not roll back the sync state on a failed submit: wgpu-core loses the device on any failed submit, so nothing continues from that state, and `Queue::submit` stays identical to trunk.
> - DX12: the one intended behavior change is the discard fix (an acquire no longer waits on the frame latency object again after a discarded frame). The root signature error log is now lossy (R4); everything else behaves as on trunk.
> - Testing: the DXGI swapchain path (both `dxgi-hwnd` and `dxgi-visual`) was run on one NVIDIA card only (RTX 4070): the `wgpu_surface` test and the `cube` example. Not tested on AMD or Intel, with validation layers, or on the timeout paths.
