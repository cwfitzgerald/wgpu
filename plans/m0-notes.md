## Settled deviations from resource-table.md (approved by Connor, 2026-07-09)

1. **D2 realization = insertion-point splice, not literally-open hal CBs.** `finish()` force-closes the encoder; only closed CBs are submitted; submit-time `open_pass` asserts closed. Mechanism instead: a `GapMarker { insertion_point = encoder.list.len(), … }` recorded at finish on `CommandBufferMutable` (mirroring `deferred_query_set_resolves`); at submit, open a fresh segment on `baked.encoder` (which `BakedCommands` retains), append exact barriers/metadata writes, `close_and_insert_at(insertion_point)`. Proven template: `DeferredQuerySetResolve` (`command/query.rs`, `command/memory_init.rs:339-396`, drained at `queue.rs:1459`). Consequence: **hal needs no open-tail/suspend contract at all** — 0.4 is table methods + trait docs only.
2. **Feature bits live at `FeaturesWGPU` word-0 bits 14/16/25** — the "use the second u64" comment was stale; that word is `FeaturesWebGPU`, structurally reserved for spec-standard features (`all_webgpu_mask` covers all of it). Word 0 is now 100% full; the next native feature requires growing `bitflags_array!`.
2b. **Feature-name strings (2026-07-09 user decision)** — stay as-is: `"wgpu-sampling-resource-table"` etc. per convention verified in feature.rs naming rules: NO feature in wgpu-types has "experimental" in its #[name] string. Universal rule is "wgpu-" + kebab-case with EXPERIMENTAL_ prefix dropped at name level. Earlier "add experimental prefix" idea is dead; do not rename.
3. **M0 shader scope: `getResource` only.** No `hasResource` anywhere (parser included) — it requires M1 metadata and would otherwise lie (D3). `T` = sampled/depth textures only (any dim/arrayed/multisampled). `getResource<sampler>` needs the M1 metadata+sampler-heap (D7: sampler slots are metadata-only) → front-end error until then; shaders take samplers from ordinary bind groups. Storage types → error pointing at the heterogeneous milestone.
4. **`getResource` index is u32-only** (abstract-int converts; concrete `i32` rejected via `AutoConversionLeafScalar`). Deviates from the proposal text ("i32 or u32"); pinned by test; add to the upstream-feedback backlog.
5. **M0 pipelines using tables require `EXPERIMENTAL_RESOURCE_TABLE_UNCHECKED`** in addition to SAMPLING (the checked path doesn't exist until M1).
6. S-bench not scheduled (its subject — open-tail cost — dissolved with deviation 1). Examples deferred per Connor; e2e tests pulled early instead.

**Landed shape — 0.8 (wgpu-core queue machinery):**
- Global entry points (resource_table.rs): `resource_table_update(id, slot, texture_view_id) -> Result<(), UpdateResourceTableError>`, `resource_table_insert_binding(id, texture_view_id) -> Result<u32, _>` (returns lowest free slot), `resource_table_remove_binding(id, slot)`. M0 texture-view-only. `ResourceTable::update_slot`/`remove_binding` are pub (player replay drives them).
- D2 splice: `ResourceTableGap { table, insertion_point }` recorded on CommandBufferMutable — compute passes record one gap per DISTINCT table bound during the pass (State::resource_tables_seen, Arc::ptr_eq dedup — post-review fix M1); render passes record the descriptor-bound table. Drained at submit in `BakedCommands::process_resource_table_gaps` (memory_init.rs, called from Queue::submit ~1485 before the Transit prologue): TWO-PHASE after review fix C1 — phase 1 sorts gaps ASCENDING by adjusted insertion point and computes texture transitions to TextureUses::RESOURCE against the shared device tracker in execution order; phase 2 splices DESCENDING via `close_and_insert_at` with the precomputed barriers. `adjust()` maps insertion points past already-spliced deferred query resolves. Transitions apply only to member textures not otherwise used in the same CB (same-CB write-then-table-sample remains a documented M0 limitation).
- Marking: `mark_all_slots_in_use(submit_index)` for every table in `baked.trackers.resource_tables`, under the table's `contents` mutex, BEFORE the hal submit — this serialization vs host updates is the Invariant-1/2 guarantee. `ActiveSubmission::contains_resource_table` wired (destroy defers).
- Teardown (review fix C2): `ActiveSubmission::contains_texture` (life.rs) now ALSO scans in-flight submissions' `resource_tables.used_resources()` consulting each table's `texture_to_slots` — so a texture referenced only via a table has its destroy deferred to the referencing submission. Airtight because the slot gate is monotonic: a slot can't be emptied while its marking submission is incomplete, so a live-contents scan can't miss an in-flight reference. New lock-rank `RESOURCE_TABLE_CONTENTS` (leaf; follower of QUEUE_LIFE_TRACKER among others; acyclic).
- `UpdateResourceTableError` gained `MissingTextureUsage` and `NoAvailableSlot`. Render-bundle rejection: `CreateRenderBundleError::ResourceTableUnsupported` at finish_inner (execute-time check is now a debug_assert).

## Wave 7 — 0.9 conflict validation + 0.10 dirty-bit barriers (a2269e51, 42040e57, 8a2816c9)

- 0.9 (`vytromoz a2269e51`, "wgpu-core: resource table usage-conflict validation"): submit-time rejection when a table-visible texture is WRITTEN in the same command buffer (v0 semantics, D3; whole-resource granularity, D9). Shape: `TextureUsageScope/TextureTracker::collect_writable_textures` (track/texture.rs); `CommandBufferMutable`/`BakedCommands` field `resource_table_writable_textures: FastHashMap<TrackerIndex, TextureUses>`; passes accumulate at pass end, feature-gated (render: from the pass scope incl. attachments — exact; compute: from `intermediate_trackers` end state); `ResourceTable::find_writable_conflict` reads LIVE table membership; errors `ResourceTableConflictError::WritableMember` → `QueueSubmitError::ResourceTableConflict`; the check runs in queue submit BEFORE slot-marking/gap-splicing so a conflicting submission aborts cleanly.
- 0.9 semantics: "written" = EXCLUSIVE texture usages (COLOR_TARGET, DEPTH_STENCIL_WRITE, STORAGE_WRITE_ONLY/READ_WRITE/ATOMIC). COPY_DST/uploads are NOT conflicts (normal population path). Cross-command-buffer and cross-submission writes remain allowed (device tracker handles them safely; per-CB catches exactly the UB cases).
- 0.9 documented gaps (flagged for W8 review / later milestones): (a) compute accumulation uses tracker end-state, so a write-then-read of the same texture across dispatches WITHIN one compute pass isn't unioned — not a safety hole (0.10 barriers keep it memory/layout-safe) but a D3-completeness gap; note lives at `TextureTracker::collect_writable_textures`. (b) Read-layout concern OUT of 0.9 scope: a table member also used as COPY_SRC / DEPTH_STENCIL_READ / STORAGE_READ_ONLY in the same CB sits in a non-SHADER_READ_ONLY_OPTIMAL layout and the 0.8 gap skips its transition — known M0 limitation, belongs to layout-override work.
- 0.10 (`wzqprvtn 42040e57` hal + `ynvunlkv 8a2816c9` core): intra-compute-pass hazard barriers, NOT descriptor rebinding (that was 0.7). New hal method `CommandEncoder::resource_table_memory_barrier()` — Vulkan: plain VkMemoryBarrier COMPUTE→COMPUTE with SHADER_READ|SHADER_WRITE both sides, no image transition; noop: no-op; dx12/metal/gles: `unimplemented!()` stubs per the existing table-stub convention. Core: two `State` bits `dirty_write`/`dirty_table_read` in command/compute.rs; `flush_resource_table_barrier()` runs once per user dispatch from `flush_bindings` after `drain_barriers`; emits when `(uses_table && dirty_write) || (has_writable && dirty_table_read)`, then clears both and sets `dirty_write |= has_writable`, `dirty_table_read |= uses_table`. "Writable" detected from user bind groups' declared usages via `has_writable_usage()` (track/buffer.rs, track/texture.rs) + `BindGroupStates::has_writable_bindings()`; injected indirect-validation dispatches don't perturb the bits.
- 0.10 notes: render passes intentionally untouched (single usage scope, barriers at pass start). In M0 the barrier is conservative/redundant for valid programs (0.9 rejects genuine same-resource write→table-read); it becomes load-bearing at M2. It IS emitted and VVL-validated by tests.
